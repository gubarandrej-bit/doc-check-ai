# DocCheck

Система проверки и глубокого анализа проектной и рабочей документации
по инженерным системам зданий на соответствие нормативно-техническим
документам (НТД) Российской Федерации.

**Охват систем:** электроснабжение, электроосвещение, противопожарные системы
(пожарная сигнализация, СОУЭ, пожаротушение), сети связи (СКС, ЛВС, ВОЛС),
видеонаблюдение, СКУД, охранная сигнализация, АСУ и АСУТП.

## Быстрый старт

```bash
git clone https://github.com/gubarandrej-bit/doc-check-ai.git
cd doc-check-ai
sudo bash install.sh       # Linux / Proxmox
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Скрипт устанавливает Docker, Node.js, npm, Python, создаёт `.env`
со случайным ключом и запускает систему. Веб-интерфейс — на порту 80.

**Вход по умолчанию:** `admin` / `admin123` (смените после первого входа).

Подробная инструкция — в [INSTALL.md](INSTALL.md).

## Что проверяется

Детерминированные проверки по расчётам и сверкам таблиц:

- соответствие марки и сечения кабеля нагрузке по ПУЭ, с запасом 1.25;
- выбор источников питания по току и мощности, коэффициент загрузки;
- ёмкость аккумуляторов по времени резервирования;
- сверка кабельного журнала со спецификацией по наименованиям и количеству;
- сверка оборудования на схемах со спецификацией;
- корректность электрических и структурных схем.

Плагины ИИ:

- `AI_DOC_TEXT` — анализ текста PDF и DOC по НТД, с цитатами из документа
  и ссылками на пункты;
- `CAD_STRUCTURE` — разбор чертежей DWG/DXF: слои, надписи, вставки блоков;
- `AI_CAD_VISION` — понимание содержимого чертежа мультимодальной моделью.

## Принцип честности

Система не выдумывает результаты. Каждая проверка имеет один из трёх статусов:

- **пройдена** — данных достаточно, нарушений не найдено;
- **нарушение** — найдено отклонение, приложены пункты НТД и доказательства;
- **не проведена** — данных или возможностей не хватило, указана причина.

Причины бывают честными: нет текстового слоя в PDF, не установлен
ODA File Converter, выбранная модель не мультимодальна. Такой ответ полезнее
выдуманного заключения.

## Режимы работы

Локальный, облачный и гибридный. Модели подключаются через веб-интерфейс:
OpenRouter и другие OpenAI-совместимые API для облака, Ollama — для локальной
работы без передачи данных наружу.

## Форматы входных данных

`xls`, `xlsx`, `doc`, `docx`, `pdf`, `dwg`, `dxf`, `zip`.

Чтение DWG требует ODA File Converter — сторонней программы, которая не
распространяется вместе с системой. Инструкция: `tools/oda/README.md`.
Альтернатива — экспорт чертежей в DXF или PDF.

## Стек

Бэкенд: FastAPI, SQLAlchemy 2, SQLite (или PostgreSQL), JWT-авторизация.
Фронтенд: React 18, Vite, Tailwind CSS, тёмная тема.
Развёртывание: Docker Compose.

## Лицензия и данные

Все расчёты и ссылки на НТД приведены в соответствии с документами, актуальными
на дату установки. Ответственность за соответствие проекта нормам лежит на
проектировщике: система — инструмент проверки, а не замена экспертизы.
